# Light Keeper

Кооперативная браузерная игра на двоих. Два стикмена, красный и голубой, с лампами
в руках проходят череду процедурно генерируемых лиминальных пространств. В каждом
нужно выжить, найти спрятанную дверь, открыть её и пройти через неё вместе.
Лампы перегреваются, и ими нужно обмениваться, как горячей картошкой. Масло
кончается, а в темноте приходят привидения. Цель — пройти как можно больше пространств.

Правила игры подробно: [docs/GAME_DESIGN.md](docs/GAME_DESIGN.md).

## Структура

| Папка     | Назначение                                                          |
| --------- | ------------------------------------------------------------------- |
| `client/` | Браузерный клиент: Vite, TypeScript, Three.js (вид от первого лица) |
| `api/`    | Игровой сервер: Node.js, TypeScript, авторитетная симуляция         |
| `shared/` | Общий код клиента и сервера: протокол, типы, константы, генерация   |

## Требования

- Node.js ≥ 22.12 (см. `.nvmrc`)
- npm ≥ 10

## Команды

```bash
npm install          # установка зависимостей всех пакетов
npm run dev          # api (http://localhost:3000) + client (http://localhost:5173)
npm run build        # сборка api (esbuild) и client (vite)
npm start            # запуск собранного api
npm run check        # prettier + eslint + typecheck + тесты + дымовой тест сборки
npm run smoke        # собрать сервер и проверить, что сборка запускается
```

В dev-режиме Vite проксирует `/api/*` на игровой сервер (адрес задаётся
переменной `API_URL`, по умолчанию `http://localhost:3000`).

## Игра вдвоём

1. Первый игрок нажимает «Создать комнату» и диктует напарнику 4-буквенный код.
2. Второй вводит код (можно в русской раскладке — буквы-двойники заменятся) и жмёт «Войти».
3. Оба нажимают «Готов» — через 3 секунды партия начинается.

Клиент и сервер общаются по WebSocket (`/api/ws` → `api:/ws`), формат сообщений
описан в `shared/src/protocol/Messages.ts`.

### Сетевая модель

- **Сервер авторитетен.** Он ведёт симуляцию 20 раз в секунду и рассылает снимки
  мира (`match:snapshot`).
- **Ввод — командами.** Каждый кадр клиент формирует команду (направление, взгляд,
  бег, длительность кадра) и отправляет их пачками раз в 50 мс. Сервер применяет
  команды тем же кодом, что и клиент (`shared/src/simulation/PlayerMovement.ts`),
  но не даёт потратить больше игрового времени, чем прошло на самом деле
  (защита от ускорения).
- **Предсказание и согласование.** Свой стикмен двигается сразу; получив снимок,
  клиент берёт позицию сервера и переигрывает неподтверждённые команды.
  Расхождение гасится плавно.
- **Напарник** рисуется с задержкой 100 мс — интерполяцией между снимками.

## Запуск в Docker

```bash
docker compose up --build
```

Игра откроется на http://localhost:8080 (порт меняется переменной `LK_PORT`,
например `LK_PORT=3001 docker compose up --build`).

- **client** — nginx со сборкой клиента; проксирует `/api/*` (HTTP и WebSocket)
  на сервер.
- **api** — игровой сервер (Node.js, один собранный файл, запускается не от root).
- Таблица рекордов хранится в томе `records` и переживает пересоздание
  контейнеров (`docker compose down -v` удалит и её).
- Отладочные команды в Docker выключены.

Файлы: `docker-compose.yml`, `docker/api.Dockerfile`, `docker/client.Dockerfile`,
`docker/nginx.conf`.

## Управление

| Клавиша                  | Действие                                    |
| ------------------------ | ------------------------------------------- |
| клик по экрану           | захватить мышь (осмотр)                     |
| мышь                     | смотреть                                    |
| `W` `A` `S` `D`          | идти                                        |
| `Shift`                  | бежать                                      |
| `E` (удерживать 3 с)     | открыть дверь                               |
| `E`                      | войти в открытую дверь                      |
| `E` (глядя на напарника) | предложить обмен лампами / согласиться      |
| `R` (удерживать 1,5 с)   | заправить лампу из канистры                 |
| `1` / `2`                | взять лампу / компас (стрелка на напарника) |
| `M`                      | выключить / включить звук                   |
| `Esc`                    | пауза (отпустить мышь)                      |

### Отладочные клавиши

Работают только в режиме разработки (`npm run dev`); сервер принимает эти команды
только с `LK_DEBUG=1` (задано в `api/.env.development`).

| Клавиша | Действие                                      |
| ------- | --------------------------------------------- |
| `N`     | оба игрока переходят в следующее пространство |
| `T`     | перенестись к двери выхода                    |
| `K`     | перенестись к ключу (в шаге от него)          |
| `O`     | перенестись к ближайшей канистре              |
| `G`     | вызвать привидение примерно в 8 м             |
| `H`     | нагреть свою лампу до 85 %                    |
| `L`     | оставить в своей лампе 12 % масла             |

## Переменные окружения (api)

См. `.env.example`:

- `PORT` — порт сервера (по умолчанию `3000`);
- `HOST` — адрес (по умолчанию `0.0.0.0`);
- `RECORDS_FILE` — файл таблицы рекордов (по умолчанию `data/records.json`
  относительно папки `api`);
- `LK_DEBUG=1` — отладочные команды (только для разработки).

Таблица рекордов отдаётся по `GET /records` (через клиент — `/api/records`).

## Соглашения

- TypeScript в строгом режиме и ООП: сущности, системы и экраны — классы
  с явными модификаторами доступа.
- Пакет `shared` подключается как исходники TS: клиент собирает его через Vite,
  сервер — через tsx (dev) и esbuild (prod).
